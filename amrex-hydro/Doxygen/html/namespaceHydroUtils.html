Compute Fluxes.

Parameters
[in]iconservArray of length ncomp giving, per component: 1 conservative, 0 convective, -1 the face array already holds the final flux. For -1 the face value is copied to the flux unchanged: no velocity, no face area, no RZ and, in the EB version, no aperture factor is applied. A caller that uses -1 together with fluxes_are_area_weighted must therefore supply a face array that is already weighted by all of those factors. -1 is only meaningful with knownFaceState = true; with knownFaceState = false the edge-state kernels treat -1 as conservative and write a predicted state into the face array, which is then copied out as the flux with no velocity factor.

Compute edge state and flux. Allows time-depdendent inflow and inflow through EB.

Note
See ComputeFluxes for the meaning of iconserv, in particular the iconserv[n] == -1 convention, which means the face array already holds the final flux and bypasses every geometric factor. It requires knownFaceState = true.
Ghost-cell requirements, when knownFaceState is false and the edge state is predicted here: q needs 3 filled ghost cells (4 for 3D EBGodunov, and BDS needs the corners as well), the MAC velocities need 1, and divu needs
  1. divu must be a valid Array4 in 3D Godunov for every component, and for BDS whenever any component is conservative.
advection_type must be one of "Godunov", "MOL" or "BDS". BDS is not available with EB.
On a level that has cut cells, the cut boxes are handled by EBGodunov, which uses PLM and adds the forces after the transverse terms. godunov_use_ppm and godunov_use_forces_in_trans are therefore ignored on every box of such a level, so that the scheme does not change from box to box and a face shared by a regular box and a cut box is computed the same way from both sides.
bc_arr, the position-dependent boundary conditions, is only supported with (EB)Godunov; passing it with "MOL" or "BDS" aborts, because those kernels would silently use h_bcrec/d_bcrec instead.

See ComputeFluxes for the meaning of iconserv, in particular the iconserv[n] == -1 convention, which means the face array already holds the final flux and bypasses every geometric factor. It requires knownFaceState = true.
Ghost-cell requirements, when knownFaceState is false and the edge state is predicted here: q needs 3 filled ghost cells (4 for 3D EBGodunov, and BDS needs the corners as well), the MAC velocities need 1, and divu needs
  1. divu must be a valid Array4 in 3D Godunov for every component, and for BDS whenever any component is conservative.
advection_type must be one of "Godunov", "MOL" or "BDS". BDS is not available with EB.
On a level that has cut cells, the cut boxes are handled by EBGodunov, which uses PLM and adds the forces after the transverse terms. godunov_use_ppm and godunov_use_forces_in_trans are therefore ignored on every box of such a level, so that the scheme does not change from box to box and a face shared by a regular box and a cut box is computed the same way from both sides.
bc_arr, the position-dependent boundary conditions, is only supported with (EB)Godunov; passing it with "MOL" or "BDS" aborts, because those kernels would silently use h_bcrec/d_bcrec instead.

Compute Fluxes in the presence of EB.

Parameters
[in]iconservArray of length ncomp giving, per component: 1 conservative, 0 convective, -1 the face array already holds the final flux. For -1 the face value is copied to the flux unchanged: no velocity, no face area, no RZ and, in the EB version, no aperture factor is applied. A caller that uses -1 together with fluxes_are_area_weighted must therefore supply a face array that is already weighted by all of those factors. -1 is only meaningful with knownFaceState = true; with knownFaceState = false the edge-state kernels treat -1 as conservative and write a predicted state into the face array, which is then copied out as the flux with no velocity factor.
Note
EB advection requires Cartesian geometry; the routine asserts on this.

Extrapolate the velocity to faces, for use as the pre-MAC velocity.

Note
Ghost-cell requirements: vel needs 3 filled ghost cells, or 4 for 3D EBGodunov; vel_forces needs 1; and velocity_on_eb_inflow, when given, needs 2.
advection_type must be one of "Godunov", "MOL" or "BDS", matching ComputeFluxesOnBoxFromState. BDS extrapolates the velocity to faces with Godunov PLM, so "BDS" here ignores godunov_ppm, and is not available with EB.
BC_MF, the position-dependent boundary conditions, is only supported with (EB)Godunov; passing it with "MOL" or "BDS" aborts, because those kernels would silently use h_bcrec/d_bcrec instead.
